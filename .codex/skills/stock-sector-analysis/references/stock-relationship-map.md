# 股票关系地图规则

当板块分析涉及热门主题、产业链、隐藏关联、补涨观察或用户要求熟悉公司关系时，使用本文件生成独立的股票关系地图报告。

## 目标

把市场中的股票从孤立名称整理成可复盘的关系图：

```text
主线 -> 子线 -> 产业链环节 -> 相关公司 -> 证据与验证
```

报告只做研究观察、信息整理和后续验证，不输出买入、卖出、持有、仓位或目标价。

## 层级定义

股票关系地图必须先拆清楚层级，再放公司。不要把主线、子线、静态行业和产业链环节用斜杠混写成同一层级。

- 主线：市场正在交易的大方向，通常由资金、成交额、涨停扩散、新闻催化和历史连续性共同确认。例如 AI 硬件、半导体国产替代、机器人、资源避险、创新药。
- 子线：主线下面可独立轮动、可单独观察强弱的方向。例如 CPO 光通信、高速 PCB、液冷、半导体设备、电子化学品、减速器、伺服电机。
- 产业链环节：公司在产业链里的具体位置，按上游、中游、下游、配套服务组织。例如萤石资源、湿电子化学品、封装测试、光模块、PCB、终端应用。
- 静态行业：`stock_basic.industry`、申万行业或交易所行业，只作为数据归类和横截面统计入口，不直接等同市场主线。

判断优先级：

```text
市场主线确认
> 子线是否独立轮动
> 产业链环节位置
> 静态行业归属
```

如果报告中出现类似 `AI硬件/半导体制造/高速互连`、`PCB/元器件/显示`、`氟化工/电子化学品` 的混写，必须重写为“主线、子线、产业链环节、静态行业”四类，并说明哪些只是相关标签，不是上下级关系。

## 固定目录

股票关系地图历史记录目录：

```text
D:\Projects\intelligent-stock-selection-system\analysis_records\stock_relationship_map
```

记录文件格式：

```text
analysis_records\stock_relationship_map\YYYY-MM\YYYY-MM-DD.md
```

如果当天文件已存在，先读取旧文件，再追加“更新版本”，不要直接覆盖。

## 分析前必须读取

生成地图前必须读取：

1. 最近 5 篇 `analysis_records/stock_relationship_map` 记录。
2. 本周所有股票关系地图记录。
3. 最近 5 篇 `analysis_records/sector_analysis` 记录。
4. 最近 5 篇 `analysis_records/stock_selection` 观察池记录。

如果没有历史地图，写明“暂无股票关系地图历史记录可检验”。

## 历史地图更新与纠错

每次生成报告时，必须单独输出“历史地图更新”：

```text
## 历史地图更新
- 新增公司：
- 新增产业链环节：
- 公司信息更新：
- 之前遗漏：
- 之前错误：
- 需要降级或证伪：
- 仍待确认：
```

判断规则：

- 如果发现之前漏掉同主题更核心公司，要明确写“之前遗漏”。
- 如果发现之前把弱相关公司当成核心，要明确写“之前错误”，并说明修正后的关系强度。
- 如果公司公告、年报、互动记录或行情验证改变了判断，要写“公司信息更新”。
- 如果只是市场概念标签、没有业务或财务证据，要降级为“映射”或“弱相关”。
- 如果公司否认相关业务、行情持续不响应或财务无法验证，要标注“证伪/降级”。

## 主题拆解流程

对当天最强 1-3 个主题执行：

```text
1. 从涨幅榜、涨停榜、成交额榜、行业/主题强度中识别已异动股票。
2. 归因：提取共同上涨原因。
3. 先确认主线，再拆出可独立轮动的子线。
4. 将每条子线拆成上游、中游、下游和配套服务。
5. 把已异动公司放到对应子线和产业链环节。
6. 主动补全同环节和上下游未异动公司。
7. 给每家公司标注关系强度和市场状态。
8. 检查公司级催化、业务证据和财务验证。
9. 生成已异动、待扩散、未启动、掉队、证伪五类。
10. 给出次日或后续验证条件。
```

不要只列涨起来的股票。必须补充“待扩散”和“未启动但相关”公司，除非数据来源不足，并在信息缺口中说明。

## 主题历史路径

生成股票关系地图时，不能只看最近 5 篇完整报告。对当天进入地图的每条主线和子线，必须读取 `analysis_records/research_context/YYYY-MM/YYYY-MM-DD.md` 里的“历史报告关键词回溯”，必要时继续按关键词查找最近 30 天历史报告。

关键词回溯只提供历史报告原文命中段落，不负责判断主题阶段。阶段判断由当前关系地图根据历史段落和最新 Tushare 数据总结。

每条主线至少判断：

```text
启动：什么时候第一次进入主线或重要分支。
强化：什么时候放量、扩散、上调。
分化：什么时候龙头和后排开始背离。
退潮：什么时候被降级、剔除或证伪。
修复：当前是首次修复、二次修复，还是退潮后的弱反抽。
证伪：哪些公司、子线或映射关系已经被市场或公司事实否定。
```

如果当前主题是修复行情，必须说明上一轮退潮位置。例如 PCB/高速互连、CPO 光通信、半导体设备材料等高频轮动主题，必须回查上一轮主线、第一次下跌和本次修复路径，不能只凭当天涨幅上调。

每家代表公司至少包含：

```text
公司：
代码：

主营业务：靠什么赚钱。
产品：卖什么；哪些产品与主题相关。
客户：卖给谁；客户关系是否有公告、年报、官网或互动记录确认。
上游：采购什么关键材料、设备或服务。
下游：服务哪个行业或应用场景。
题材：被市场归到哪些故事里；概念强弱如何。
催化：最近为什么动；区分公司级事实、板块催化和市场推测。
财务验证：收入、利润、订单、产能或毛利率是否体现主题逻辑。
市场验证：涨跌幅、成交额、换手、资金、龙虎榜、相对行业强弱。
信息缺口：收入占比、客户关系、订单金额、产品阶段等缺失项。
观察条件：
失效条件：
```

## 关系强弱分层

| 层级 | 判断标准 |
| --- | --- |
| 核心 | 主营业务直接对应主题，收入、利润、订单或产能能验证 |
| 相关 | 有明确产品、客户或业务，但不是绝对主业 |
| 映射 | 逻辑能讲通，但业务占比、客户或订单不清楚 |
| 弱相关 | 少量业务、参股、互动回复或市场联想 |
| 证伪 | 公司否认、业务无实质进展、行情不响应或财务无法验证 |

证据优先级：

```text
公告/年报/招股书/官网事实
> 投资者关系活动记录和互动平台
> 行业新闻和客户线索
> 研报观点
> 市场概念标签
> 传闻和名称联想
```
